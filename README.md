# 영화 평점 관리 데이터베이스

SQLite를 사용해 **영화 평점 관리 도메인**의 관계형 데이터베이스를 설계하고, PK/FK/제약조건을 적용한 뒤 샘플 데이터를 입력하여 조회·조인·집계·서브쿼리·수정·삭제·인덱스 생성까지 실습한 프로젝트입니다.

백엔드 프레임워크는 사용하지 않았으며, SQL 관점에서 테이블 간 관계와 데이터 무결성을 직접 확인하는 것을 목표로 했습니다.

---

## 1. 개발 환경

- OS: macOS
- DB: SQLite
- SQL 실행 도구: VS Code + SQLite Extension
- 백엔드 프레임워크: 사용하지 않음
- ERD: dbdiagram.io

> SQLite의 외래 키 검사는 DB 연결 단위로 활성화되므로 외래 키 검증이 필요한 실행에서는 `PRAGMA foreign_keys = ON;`을 사용합니다.

## 3. 데이터 모델

### 테이블 구성

| 테이블 | 역할 | 주요 키 |
| --- | --- | --- |
| `member` | 회원 정보 관리 | PK: `member_id` |
| `genre` | 영화 장르 관리 | PK: `genre_id` |
| `movie` | 영화 정보 관리 | PK: `movie_id`, FK: `genre_id` |
| `review` | 회원의 영화 리뷰 및 평점 관리 | PK: `review_id`, FK: `member_id`, `movie_id` |

### 1:N 관계

- `genre` 1 : N `movie`
  - `movie.genre_id` → `genre.genre_id`
- `member` 1 : N `review`
  - `review.member_id` → `member.member_id`
- `movie` 1 : N `review`
  - `review.movie_id` → `movie.movie_id`

따라서 최소 2개 이상의 1:N 관계 요구사항을 충족하며, 실제로는 총 3개의 1:N 관계를 구성했습니다.

## 5. 제약조건

스키마에는 다음과 같은 데이터 무결성 규칙을 적용했습니다.

| 제약조건 | 적용 예시 | 목적 |
| --- | --- | --- |
| `PRIMARY KEY` | 각 테이블의 ID | 행을 유일하게 식별 |
| `FOREIGN KEY` | `movie.genre_id`, `review.member_id`, `review.movie_id` | 테이블 간 참조 무결성 유지 |
| `NOT NULL` | 이름, 이메일, 제목, 평점 등 | 필수 값 누락 방지 |
| `UNIQUE` | `member.email`, `genre.genre_name` | 중복 데이터 방지 |
| `CHECK` | `rating BETWEEN 1 AND 5` | 평점을 1~5 범위로 제한 |

SQLite에서 FK 검사를 활성화하기 위해 다음 SQLite 전용 문법을 사용했습니다.

```sql
PRAGMA foreign_keys = ON;
```

## 9. 보너스 과제

### 보너스 1. 같은 요구를 JOIN과 서브쿼리로 해결

요구사항은 **리뷰를 한 번도 작성하지 않은 회원 조회**로 정했습니다.

#### LEFT JOIN 방식

```sql
SELECT m.member_id
     , m.name
  FROM member AS m
  LEFT JOIN review AS r
    ON m.member_id = r.member_id
 WHERE r.review_id IS NULL;
```

#### NOT EXISTS 서브쿼리 방식

```sql
SELECT m.member_id
     , m.name
  FROM member AS m
 WHERE NOT EXISTS (
       SELECT 1
         FROM review AS r
        WHERE r.member_id = m.member_id
       );
```

두 쿼리 모두 동일한 결과를 반환합니다.

| member_id | name |
| --- | --- |
| 10 | 임하늘 |

- `LEFT JOIN` 방식: 회원과 리뷰를 연결한 뒤 리뷰가 연결되지 않아 `NULL`인 회원을 찾습니다.
- `NOT EXISTS` 방식: 각 회원에 대해 해당 회원의 리뷰가 존재하지 않는지를 검사합니다.

### 보너스 2. 데이터 정합성 깨뜨려 보기

`review.member_id`가 `member.member_id`를 참조하도록 FK가 설정되어 있으므로 존재하지 않는 `member_id = 999`를 참조하는 리뷰를 입력하면 DB가 저장을 거부합니다.

해당 검증은 텍스트 결과 대신 실제 VS Code SQLite 실행 오류 화면으로 남겼습니다.

![보너스 2 FK 무결성 오류](docs/bonus2-error.png)

오류 원인은 자식 테이블인 `review`가 부모 테이블 `member`에 존재하지 않는 ID를 참조했기 때문입니다. 해결하려면 기존 회원 ID를 사용하거나, 필요한 회원 데이터를 `member` 테이블에 먼저 생성한 후 리뷰를 입력해야 합니다.

## 10. 인덱스 적용

영화별 리뷰를 조회하거나 영화와 리뷰를 JOIN할 때 자주 사용하는 `review.movie_id`에 인덱스를 생성했습니다.

```sql
CREATE INDEX idx_review_movie_id
    ON review(movie_id);
```

적용 이유:

> `review.movie_id`는 영화별 리뷰 검색 및 `movie`와 `review`의 JOIN 조건으로 사용되므로 조회 성능 향상을 위해 인덱스를 생성했습니다.

SQLite에서 인덱스 생성 여부는 `PRAGMA index_list(review);`로 확인할 수 있으며 `idx_review_movie_id`가 생성된 것을 확인했습니다.

## 11. SQLite 전용/비표준 문법

과제 요구사항에 따라 가능한 범위에서 표준 SQL 문법을 사용하고, SQLite에서 사용하는 문법은 SQL 파일에 주석으로 명시했습니다.

| 문법 | 사용 목적 |
| --- | --- |
| `PRAGMA foreign_keys = ON` | 현재 SQLite 연결에서 FK 제약조건 활성화 |
| `PRAGMA foreign_key_list(...)` | FK 정의 확인 |
| `PRAGMA index_list(...)` | 인덱스 생성 여부 확인 |
| `LIMIT` | 조회 결과 행 수 제한 |

`LIMIT`은 여러 DBMS에서 지원하지만 SQL 표준의 행 제한 문법과는 차이가 있으므로 SQLite에서 지원하는 문법임을 쿼리 주석에 표시했습니다.

## 12. 실행 방법

### 기존 DB 확인

VS Code의 SQLite Extension에서 `0.movie_rating.db3`를 열어 테이블 및 데이터를 확인할 수 있습니다.

### 처음부터 재현

기존 `0.movie_rating.db3`에 `1.schema.sql`을 다시 실행하면 이미 생성된 테이블 때문에 오류가 발생할 수 있습니다. 처음부터 재현하려면 **새로운 빈 SQLite DB 파일**을 만든 뒤 아래 순서대로 실행합니다.

```text
1.schema.sql
      ↓
2.sample_data.sql
      ↓
3.queries.sql
```

1. `1.schema.sql`
   - 4개 테이블 생성
   - PK/FK/NOT NULL/UNIQUE/CHECK 설정
2. `2.sample_data.sql`
   - `member` 10행
   - `genre` 10행
   - `movie` 10행
   - `review` 11행 입력
3. `3.queries.sql`
   - 필수 SQL Q1~Q15 실행
   - 보너스 과제 실행

> `UPDATE`, `DELETE`, `CREATE INDEX`는 DB 상태를 변경하므로 동일한 DB에서 전체 쿼리 파일을 반복 실행할 경우 결과나 오류가 달라질 수 있습니다.
